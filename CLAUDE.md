# MGA Online Shop — catatan untuk agent

- Laravel 13, PHP 8.3+, MySQL (test pakai SQLite in-memory), Tailwind v4 + Alpine.js, Blade (tanpa Livewire/Inertia).
- Bahasa UI: Indonesia. Locale `id`, timezone `Asia/Jakarta`.
- Peran user: `App\Enums\UserRole` (admin/customer). Route dilindungi middleware `role:admin` / `role:customer`.
- Kolom `role` dan `is_active` sengaja tidak mass-assignable; ubah dengan `forceFill`.
- Pembayaran & ongkir lewat interface `App\Contracts\PaymentGateway` dan `App\Contracts\ShippingProvider`; driver dipilih di `AppServiceProvider` dari `config/shop.php`.
- Perubahan status pesanan lewat `App\Services\Orders\OrderService` (aturan transisi ada di `OrderStatus::nextStatuses()`).
- Brand: logo resmi = `<x-logo>` (SVG inline; `variant="mark"`, `dark`, `mono`), aset di `public/images/brand`. Warna di `resources/css/app.css`: `brand-*` teal (utama, logo `brand-500` #21939F), `accent-*` oranye (promo/diskon, logo `accent-400` #F68E55). Font Poppins self-hosted via `@fontsource/poppins`.
- Komponen Blade: `resources/views/components` (layout `x-layouts.shop|admin|account|auth`, `x-icon`, `x-product-card`, dll). Kelas utilitas `.btn`, `.input`, `.card`, `.badge` di `resources/css/app.css`.
- Form: pakai komponen `resources/views/components/form` (`x-form.input|money|number|phone|date|date-range|select|category-select|textarea|image-upload|file|errors|field|switch`). On/off (Aktif, tampilkan, sinkron otomatis) = `<x-form.switch name label description [card] [tooltip] :checked>` (saklar `.switch`, selalu kirim `0`/`1` jadi `old()` benar; controller pakai `$request->boolean()`), jangan checkbox polos dengan teks kecil inline. Tombol simpan form admin dibungkus `<x-admin.save-bar>` (menempel di bawah layar < lg). Isian berulang (varian, tarif per metode) = kartu/baris grid dengan container query (`@container`, `@xl:grid-cols-3`), bukan tabel lebar yang perlu digeser. Label, petunjuk, `old()` dan error sudah ditangani. Perilaku JS = directive Alpine di `resources/js/forms` (`x-searchable` Tom Select, `x-datepicker[.time]`/`x-daterange` flatpickr bahasa Indonesia, `x-money` ribuan Rupiah → terkirim angka bersih, `x-phone`); library di-import dinamis, CSS di-host lewat npm. Di dalam template Alpine pakai `x-bind:name`, bukan `:name`.
- Tooltip bantuan: `<x-tooltip label="SKU" text="Fungsi isian" :tips="['Saran agar maksimal', '...']" />` (ikon ? kecil; hover di desktop, ketuk di HP, Tab/Esc untuk keyboard). Di komponen `x-form.*` cukup prop `tooltip="..."` + opsional `:tooltip-tips="[...]"` (ikon muncul di samping label). Label manual: bungkus `<div class="label-row"><label class="label">…</label><x-tooltip … /></div>`. Perilaku di `resources/js/components/tooltip.js` (delegasi event; panel dipindah ke `<body>` saat terbuka, jadi aman di card/tabel/modal), gaya `.tip-*` di `app.css`. Setiap isian admin baru yang fungsinya tidak jelas (kode, slug, SEO, batas/kuota, kunci API, jadwal) wajib diberi tooltip; isian gambar sebutkan tampil di mana + ukuran/rasio ideal untuk desktop & HP. Teks Indonesia, singkat; jangan mengulang `hint`. Di atribut statis pakai tanda kutip “ ” (bukan `&quot;`).
- Jalankan `php artisan test` sebelum commit.
- Link mati dicek otomatis oleh `tests/Feature/LinkCrawlTest.php` (menjelajahi semua `<a href>` internal dengan data demo untuk tamu, pelanggan, Superadmin, Gudang, CS; 404/403/500 = gagal). Halaman baru yang tidak terjangkau link perlu ditambah ke titik awalnya.
- Produk nonaktif: detail 404 untuk tamu/pelanggan, staf bisa pratinjau (`Product::isViewableBy()`, banner "Pratinjau admin", noindex). Di halaman pelanggan (wishlist, pesanan, ulasan) jangan beri link ke produk dengan `is_active = false`.
- Katalog: kategori maks 2 tingkat (`parent_id`), galeri `ProductImage` (sampul = `sort_order` terkecil, `Product::coverImage` selalu di-eager-load), varian `ProductVariant`. Produk bervarian (`has_variants`) menyimpan ringkasan harga termurah & total stok varian aktif lewat `Product::syncVariantSummary()`.
- Stok (`products.stock`, `product_variants.stock`) tidak mass-assignable. Ubah selalu lewat `App\Services\Catalog\StockService` (adjust/set) supaya terkunci & tercatat di `stock_movements`.
- Kunci keranjang di session: `"{product_id}"` atau `"{product_id}-{variant_id}"`. Form keranjang ber-`data-cart-form` dikirim lewat fetch (`resources/js/components/cart.js`): `CartController` membalas JSON (pesan, `cart_count`, untuk halaman keranjang `html` dari `shop.partials.cart-content`), tanpa JS tetap redirect + flash. Badge pakai `$store.cart.count`. Tombol `data-cart-native` (Beli sekarang) dikirim biasa. Pesan tambah = jumlah yang baru ditambahkan, bukan total.
- Promo: voucher lewat `App\Services\Promo\VoucherService` (cek syarat, hitung potongan, kode terpasang di session `checkout_voucher`). Kuota & batas per pelanggan dihitung dari pesanan yang tidak dibatalkan (`Voucher::redemptions()`), jadi pembatalan otomatis mengembalikan kuota. `orders.total` = subtotal − discount + shipping_cost − shipping_discount; Midtrans menerima potongan sebagai item `VOUCHER` bernilai negatif. Banner beranda: model `Banner` (scope `visible`).
- Impor/ekspor katalog: `App\Services\Catalog\Transfer` (OpenSpout, xlsx/csv). Alur: unggah → `ProductImport` (validating → ready → importing → completed) → pratinjau error per baris → commit. File > 300 baris lewat antrean (`ProcessProductImport`). Format ekspor produk = template impor. Impor produk butuh `catalog.manage`, update stok massal butuh `stock.manage`.
- Login Google pelanggan: Firebase Authentication (`x-firebase-login`, `POST /masuk/google`). Token diverifikasi `App\Services\Auth\FirebaseTokenVerifier` (sertifikat publik Google, tanpa service account), akun dicocokkan `FirebaseLoginService` lewat `users.firebase_uid` (tidak mass-assignable) / email terverifikasi. Staf tidak bisa login Google. Aktif bila `FIREBASE_API_KEY` + `FIREBASE_PROJECT_ID` terisi; setup di `docs/FIREBASE.md`.
- Beranda: hero (foto, teks, 2 tombol) & pengumuman topbar diatur di Admin › Tampilan Beranda (`Admin\StorefrontController`, disimpan lewat `StoreSettings` kunci `shop.storefront.*`, dibaca via `App\Support\Storefront`). Tanpa foto → ilustrasi `public/images/hero/hero-default*.svg`. Tab "Best Seller" (`App\Services\Storefront\BestSellers`): mode Otomatis = terjual 90 hari dari pesanan berstatus revenue (cache 30 menit), dilengkapi produk unggulan/terbaru; mode Manual = pilihan & urutan admin (`shop.storefront.best_seller_products`, nonaktif/stok habis dilewati), opsional dilengkapi otomatis; urutan di tab diganti di browser (CSS `order`). Kartu gaya tile: `<x-product-tile>`.
- Integrasi (Admin › Integrasi, `Admin\IntegrationController`): driver & kunci Midtrans/RajaOngkir/Firebase disimpan lewat `StoreSettings` (tipe `secret` = terenkripsi APP_KEY, tidak pernah ditampilkan/di-log utuh), .env sebagai cadangan; tombol "Tes koneksi" = `IntegrationTester`. Hanya jabatan Owner (label "Superadmin") lewat izin `integrations.manage`.
- Artikel/blog: `Article` + `ArticleCategory` (publik `/artikel`, admin `admin.articles.*`, izin `articles.manage`). Simpan lewat `App\Services\Content\ArticleService` (slug unik, HTML disaring `ArticleSanitizer` / symfony html-sanitizer, produk terkait, sampul). Terjadwal = status `published` + `published_at` di masa depan (scope `published`). Editor Tiptap = Alpine `articleEditor` (gambar diunggah ke `admin.articles.images`, folder `articles/content`). Gaya isi artikel: kelas `.article-prose`. Masuk sitemap & seksi "Artikel terbaru" beranda.
- Daftar admin: pakai `App\Support\AdminList::paginate($query, $request, $default)` (+ `AdminList::sort()` untuk `?sort=kolom|-kolom`) dan `<x-admin.pagination :paginator label="..." />`, `<x-admin.sort-link column>`, `<x-admin.sort-select>`, `<x-admin.keep-query />` di form filter. Pilihan baris per halaman diingat di session per daftar. Link ke halaman lain dibungkus `@can` sesuai izin route-nya (cek jabatan Gudang/CS).
- Konfirmasi & notifikasi: jangan pakai `confirm()`/`alert()` bawaan browser. Tambah `data-confirm="..."` (+ `data-confirm-title`, `data-confirm-ok`, `data-confirm-tone="danger|primary"`) di `<form>`/tombol submit, atau `<x-confirm-delete>`; dari JS `await window.confirmDialog({...})` dan `window.toast(pesan, 'success|error|warning|info')` (`resources/js/components/dialogs.js`, markup di `components/flash.blade.php`). Flash session `success|error|warning|info|status` otomatis jadi toast.
- Sidebar admin bisa diciutkan (ikon + tooltip), status di cookie `admin_sidebar` (tidak dienkripsi, dibaca Blade supaya tidak berkedip).
- Tombol WhatsApp melayang: `<x-whatsapp-float>` di `x-layouts.shop` (nomor `shop.whatsapp` format 62xxx, on/off `shop.whatsapp_button`, pesan pembuka `shop.whatsapp_message`, diatur di Admin › Pengaturan Toko). Halaman bisa menambah konteks lewat prop layout `whatsapp-context` (dipakai di detail produk). Posisi di HP lewat kelas `.whatsapp-float` (di atas navigasi bawah / bar beli).
- Katalog asli MGA (toko Shopee gudang.acc, disalin dari mga-advertising.co.id karena Shopee memblokir akses otomatis): `database/data/mga-catalog.json` → `App\Services\Catalog\MgaCatalog`. Dipakai `DatabaseSeeder` (tanpa foto) dan `php artisan shop:import-mga [--images] [--replace] [--stock=25] [--force]`. Produk yang sudah ada (slug) tidak ditimpa; produk tanpa harga masuk nonaktif. `--replace` menghapus produk non-MGA (yang pernah dipesan hanya dinonaktifkan). Foto diunduh lewat `ImageDownloader`, jadi butuh internet di server.
- Daftar pelanggan (produk/kategori/pencarian, artikel, pesanan, wishlist, ulasan) = infinite scroll: bungkus item dengan `@fragment('infinite-list') <x-infinite-list :paginator label skeleton="product|article|order|review" items-class="grid ..."> … </x-infinite-list> @endfragment`, controller membalas `App\Support\InfiniteScroll::respond($request, view(...))` (header `X-Infinite-Scroll` → hanya potongan daftar). JS `resources/js/components/infinite-scroll.js`: muat otomatis (IntersectionObserver), tiap 4 kali jeda dengan tombol "Muat lebih banyak", `:auto="false"` = tombol saja, item & posisi dipulihkan saat Back. Tanpa JS tampil link halaman (`resources/views/vendor/pagination/tailwind.blade.php`, gaya toko).
- Galeri detail produk: jalur scroll-snap (geser di HP), thumbnail vertikal di kiri pada `lg`, zoom saat kursor diarahkan (desktop), klik/ketuk = lightbox PhotoSwipe (di-import dinamis di `product-page.js`, cubit/zoom).
- Responsif HP: grid yang kolomnya baru diatur di breakpoint (`lg:grid-cols-3`) wajib diberi `grid-cols-1` juga, supaya isi panjang (Tom Select, input) tidak mendorong halaman melebar di 320px. Tabel admin di HP: sembunyikan kolom sekunder (`hidden sm:table-cell`) dan tampilkan ringkasannya di sel pertama (`sm:hidden`); tabel yang tetap lebar boleh digeser (`overflow-x-auto` + `.table-base` otomatis dapat bayangan tepi). Input di layar sentuh otomatis 16px (mencegah zoom iPhone). Cek dengan `node scripts/check-mobile-overflow.mjs` (butuh `php artisan serve`, data demo, Playwright) sebelum merge perubahan tampilan.
- Rating & terjual: `products.rating_avg/review_count` (ReviewService::syncSummary) dan `products.sold_count` (pcs dari pesanan berstatus revenue, `App\Services\Catalog\SoldCountService`, otomatis disinkron saat status pesanan masuk/keluar revenue lewat hook `Order::updated` di AppServiceProvider). Tampil di kartu lewat `<x-product-stats>` (dipakai `x-product-card` & `x-product-tile`), label ringkas `Product::soldLabel()` (1,2rb, 10rb+). Urutan katalog `?urut=terlaris|rating`. Ulasan di detail bisa disaring `?bintang=1..5`. Data demo: `php artisan shop:demo-activity --reset [--force]` (hapus semua pesanan & ulasan, buat contoh baru untuk katalog saat ini; diblok di produksi), `--sync` = hitung ulang saja. Rating demo dijaga ≥ 4,7 (`DemoRatingBooster`, hanya ulasan akun `@mga.test`); data lama dinaikkan tanpa reset lewat `php artisan shop:demo-ratings [--min=4.7] [--dry-run] [--force]` (diblok di produksi).
- Halaman bayar (`account.orders.payment`): tanpa popup. Checkout tidak membuat tagihan; pembeli memilih metode di halaman (`partials/payment-methods`), lalu `PaymentService::choose()` membuat tagihan. Midtrans Core API `/v2/charge` untuk VA/Mandiri Bill/QRIS/GoPay/ShopeePay/Indomaret/Alfamart (nomor VA, kode, QR, deeplink disimpan di `payments.instructions`, tampil lewat `partials/payment-instructions` + langkah `App\Support\PaymentInstructions`); kartu & PayLater = Snap yang disematkan (`snap.embed`, `PaymentMethod::channel()` = `snap`). QR dirender di browser dari `qr_string` (npm `qrcode`, import dinamis). Status dicek otomatis lewat `account.orders.payment.status` (JSON). Driver fake memberi contoh nomor/QR. Metode baru di Midtrans perlu diaktifkan juga di dashboard Midtrans.
- Pajak, biaya & invoice (Admin › Pajak & Biaya, `Admin\BillingSettingController`, izin `billing.manage`, disimpan `StoreSettings` kunci `shop.billing.*`, dibaca lewat `App\Services\Billing\BillingSettings`). `PriceCalculator` = biaya layanan + PPN (belum/sudah termasuk harga, DPP harga jual / nilai lain 11/12, opsional atas ongkir) + pembulatan → disalin ke kolom pesanan (`service_fee`, `tax_*`, `rounding`); `orders.total` = subtotal − discount + shipping_cost − shipping_discount + service_fee + PPN (bila belum termasuk) + rounding. `FeeCalculator` = tarif Midtrans per metode (`App\Enums\PaymentMethod`, persen + tetap + PPN atas biaya, ditanggung `buyer`/`store`, opsi gross-up). Ada metode ditanggung pembeli → pembeli memilih metode di halaman bayar (`account.orders.payment.method`), Snap dibatasi `enabled_payments`, biaya jadi item `FEE`; tagihan = `payments.amount` (total + `payments.fee`). Saat lunas: `orders.payment_method/payment_fee/gateway_fee` (perkiraan potongan dari tarif saat itu; `amountPaid()`, `netReceived()`). Tampilkan rincian tagihan selalu lewat `<x-order-totals>` / `App\Support\OrderSummary` (juga email & PDF). Nomor invoice: `InvoiceNumberer` (tabel `invoice_sequences`, terbit saat lunas/dibuat, hook di AppServiceProvider); invoice HTML `orders/invoice` + PDF Dompdf `orders/invoice-pdf` lewat `InvoiceRenderer`. Laporan tab "Keuangan & pajak" + ekspor `pajak`/`metode`. Thread penjualan manual memakai service yang sama.
- SEO: `x-layouts.base` mengatur title/description/canonical/robots/OG (`App\Support\Seo`, `SEO_INDEXING=false` di staging = noindex + robots.txt tutup), JSON-LD lewat `App\Support\StructuredData` (produk, artikel, breadcrumb, katalog `CollectionPage`, beranda `WebSite`), `sitemap.xml`/`robots.txt` dinamis. Produk & kategori punya `meta_title`/`meta_description` opsional (`seoTitle()`, `metaDescription()`, isian `<x-admin.seo-fields>`). Admin › SEO (`Admin\SeoSettingController`, izin `settings.manage`, kunci `shop.seo.*`): judul beranda (`Seo::homeTitle()`, prop layout `seo-title` = isi `<title>` utuh), deskripsi toko, gambar bagikan bawaan, kode verifikasi Google/Bing, ID GA4 (tidak dimuat di admin). Halaman publik baru wajib punya judul & deskripsi sendiri; halaman privat tambahkan ke `Seo::PRIVATE_ROUTES` + `RobotsController`.
- Kurir: daftar `StoreSettings::COURIERS` = 13 kurir resmi RajaOngkir Komerce (kode lain ditolak API 422 → seluruh cek ongkir gagal; `StoreSettings::activeCouriers()` membuang kode lama seperti `anteraja`). `TRACKABLE_COURIERS` = yang resinya bisa dilacak. Tombol "Cek rekomendasi RajaOngkir" di Pengaturan Toko (`admin.store-settings.couriers`, `App\Services\Shipping\CourierRecommender`): cek tarif semua kurir dari kecamatan asal ke sekitar gudang + kota besar di provinsi lain, direkomendasikan = punya tarif ke semua tujuan, cache 12 jam; hanya aktif bila driver RajaOngkir + API key terisi.
- Sinkron stok warehouse29 (repo eganproject/warehouse29, kontrak `docs/API_STOK_GUDANG.md` di sana): tarik `GET /api/v1/stocks` (token Bearer, IP server toko di-allowlist di warehouse29) lewat `App\Services\Warehouse\WarehouseClient` + `WarehouseStockSync`. Stok toko = qty gudang (bulat ke bawah; `inactive`/`deleted` = 0) − jumlah di pesanan website berstatus `OrderStatus::awaitingShipmentStatuses()`, diubah via `StockService::set` jenis `WarehouseSync`. Cocok lewat `products.warehouse_sku` / `product_variants.warehouse_sku` (tidak mass-assignable, `forceFill`), cadangan SKU toko yang sama persis; produk bervarian per varian. Salinan stok gudang `warehouse_stock_items`, riwayat `warehouse_sync_runs` (`server_time` = `updated_since` berikutnya). Jadwal `warehouse:sync-stock` tiap interval + `--full` 02.40. Pengaturan di Admin › Integrasi (kartu warehouse), halaman Stok › Sinkron gudang (`admin.stock.warehouse`, izin `stock.manage`) untuk sinkron manual & hubungkan SKU.
- Grosir (harga bertingkat): `products.wholesale_tiers` (tanpa varian) / `product_variants.wholesale_tiers` (per varian) = `[{min_qty, price}]`, dirapikan otomatis saat simpan (`App\Services\Catalog\Wholesale::normalize`, maks 5 tingkat, jumlah naik & harga turun di bawah harga normal). Ringkasan `products.wholesale_min_qty` (badge "Grosir", filter `?grosir=1`, scope `wholesale`) dihitung hook `saving` / `syncVariantSummary()`. Tingkat ditentukan dari jumlah GABUNGAN semua varian produk di keranjang (`CartLine::productQuantity`), dipakai juga di `CheckoutService`; `order_items.regular_price` terisi bila baris memakai harga grosir (invoice, `OrderSummary` "Termasuk hemat harga grosir", laporan `wholesaleBreakdown`). `products.min_order_qty` = minimal beli gabungan varian (keranjang menahan checkout, `CartService::belowMinimum()`). Voucher untuk barang grosir diatur saklar `shop.wholesale.voucher_combinable` (Pengaturan Toko); nonaktif = `CartService::voucherSubtotal()` tanpa baris grosir. Impor/ekspor kolom `harga_grosir` ("10=65000; 50=60000", 0 = hapus) & `minimal_beli`. Form admin: `<x-admin.wholesale-tiers>`.
